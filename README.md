# 未界社群小程序

微信原生小程序 + 微信云开发 CloudBase。仅包含社群小程序代码，不包含外层医学职业简历项目资料。

当前状态：基础导航、活动浏览、服务端身份与权限、管理员保存草稿和发布活动的本地代码已完成。前端新增多页面视觉统一与自定义导航；11组页面回归、导航与图片失败检查、10组后端替身检查通过。AppID与云环境按各自本机配置；本轮未部署、未完成真实身份、数据库规则及双账号验收。

视觉验收入口：[多页面预览](preview/design/index.html)。包含活动、资源、连接、我的及两类活动详情，可切换320/390宽度和活动异常状态。预览由原生页面文件生成，仍是浏览器对照，不能替代微信开发者工具与真机验收。详细变更、素材来源与检查说明见 [本轮交接](preview/design/README.md)。

目录分工：书玉主要修改 `miniprogram/`；余同学主要修改 `cloudfunctions/`、`database/` 和云环境配置文档。`miniprogram/services/` 由书玉维护，接口变化须先与余同学确认。公共项目配置由当次任务负责人修改，避免同时编辑。

## 导入与检查

用微信开发者工具导入本仓库根目录；源码目录由 project.config.json 指向 miniprogram/。

当前默认云端模式，环境未配置时会明确报错，不自动返回演示数据。仅查看第一阶段演示时，可临时将 miniprogram/config.js 的 mode 改为 demo；验收后恢复 cloud，演示模式没有真实身份或管理功能。

在仓库根目录执行：

```sh
node check.cjs
node check-cloud.cjs
```

这些是本地逻辑检查，不是微信开发者工具渲染或真实云端验收。

- [开发进度](开发进度.md)：按阶段追加结果与未验证项。
- [云环境配置](云环境配置.md)：集合规则、管理员初始化、部署与真实验收步骤。

## 最简单的协作约定

1. main 保存已检查、可交接的版本；当前基线仍未通过真实云端验收。
2. 每次只处理一个任务，用短期分支提交；不要两个人同时修改同一文件。
3. 合并请求写明“修改内容、实际检查、未验证事项”；另一人复核后合并。余同学重点检查后端权限与数据安全，书玉重点检查页面和业务体验；权限判断以测试与真实账号验收为依据，不要求书玉凭感觉作安全审查。
4. 不提交真实成员资料、数据库导出、密钥、凭据、node_modules 或本地工具配置。账号授权通过平台权限管理，不共享密码。
5. GitHub 协作权限、小程序开发权限、CloudBase 环境权限是三套不同权限，分别授予。持有仓库权限不等于获得云资源管理权限。
6. 当前不配置自动部署、不发布、不接入支付或订单；外部环境操作另行确认授权。

## 下一步只完成这条链路
